# BrainADZ Hospitality OS

Hotel property management and financial intelligence: reservations, booking calendar, front
desk, housekeeping, rooms, rates, guests, folios and tax invoices, general ledger, night audit,
and an executive dashboard driven by one metrics engine. It lives alongside the BrainADZ HRMS in
this repository and shares its stack (Express 5, `node:sqlite`, React 19, Vite); the HRMS is
untouched.

Requirements, architecture, schema, metric definitions, status and roadmap are in
[`../docs`](../docs): start with [`MODULE_STATUS.md`](../docs/MODULE_STATUS.md) for what works
today and what does not.

## Run it

Node.js 22.13 or newer.

```bash
npm install
npm run hos:build      # build the web client
npm run hos:start      # http://localhost:3100
```

On first start the server creates a **demo environment** in `hospitality/data/` and shows a
progress screen while it simulates a year of operations (about three minutes). Later starts are
instant. `npm run hos:reset` deletes the database so the next start builds it again.

For development, `npm run hos:dev` runs the API with auto-restart and the Vite dev server on
http://localhost:5174.

### Settings (environment variables)

| Variable | Default | Meaning |
|---|---|---|
| `PORT` / `HOST` | `3100` / `0.0.0.0` | Where the server listens (the property hub serves browsers on the LAN) |
| `DATA_DIR`, `DB_FILE` | `hospitality/data`, `hospitality.db` | Database and uploaded files |
| `SEED` | `demo` | `empty` starts with one organisation and an administrator instead of the demo |
| `DEMO_PROFILE` | `full` | `test` builds a smaller demo (about two months of history) quickly |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ORG_NAME`, `REPORTING_CURRENCY` | — | Used with `SEED=empty`; without a password a random one is printed once and must be changed at first sign-in |

## Demo environment

**Lumora Hotels & Resorts (demo)** is fictional: five properties — New Delhi (62 rooms), Mumbai
(48), Goa (42), Jaipur (30) and Lisbon (36, EUR) — with guests, companies, rates, stays, folios,
invoices and journals generated by running the real services day by day through a night audit.
Every screen says it is demo data, and the books reconcile (Finance → Reconciliation).

use. No channel manager, payment gateway or e-invoicing connection is live.

## Tests

```bash
npm run hos:test       # 54 unit, service, workflow, security and metrics tests
npm run hos:e2e        # 6 Playwright journeys (desktop 1440×900, tablet 1024×768)
npm run test:all       # HRMS + hospitality node:test suites
```

The first test run builds a compact seeded demo (about 30 seconds) and caches it in the OS temp
directory; later runs take a few seconds. E2E screenshots are written to `tests/e2e/output/`.

## Layout

```
hospitality/
  server/
    app.js, index.js         app factory and entry point
    core/                    money, dates, ids, validation, permissions, access, audit, outbox, idempotency, TOTP
    db/                      connection and migrations
    modules/<module>/        service.js (domain logic, transactions) + routes.js (HTTP)
    seed/                    demo simulation and empty start
  client/src/
    components/              design system, top-navigation shell, charts, data table, booking form
    pages/                   one file per screen
    styles/                  tokens, app and page styles
  tests/                     node:test suites, fixture hotel, Playwright runner
```
